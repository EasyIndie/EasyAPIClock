# ADR-0009：设置中的预览、登录启动与自动规则更新

- 状态：已接受
- 日期：2026-10-26
- 决策依据：用户授权按设置评估建议继续实现。

## 决策

1. 提醒预览只响应用户点击，正文明确标识测试，不表示价格切换。关闭强度不预览；中等一次，强最多三次（1/4/7秒），10秒自动清理，面板提供停止入口。独立通知ID前缀，不修改正式排程。权限不足如实反馈，不主动反复请求。
2. 登录启动仅Mac，通过ServiceManagement主应用服务，默认关闭；显示系统真实状态、审批与失败，不将开关偏好当注册结果。不引入辅助守护进程。
3. 自动规则检查默认开启，启动/唤醒/每分钟刷新中仅在距上次尝试至少6小时后检查（记录失败也节流）；手动检查不受节流。关闭不影响本地规则与通知偏好；关闭期间丢弃在途自动更新结果。使用已有整包校验与安装流程。
4. 新设置留在固定尺寸的原位滚动区域。iOS仍为只读外壳，不增加上述交互。

## 验证与限制

用固定时间测试自动检查节流与开关、预览次数与上限。通知投递受系统权限、Focus与静音限制。登录启动注册及登录后的启动需在安装位置稳定的应用上验证；开发构建不得假称已完成登录验收。

## 平台依据

Apple官方SMAppService文档：https://developer.apple.com/documentation/servicemanagement/smappservice 。主应用登录项通过register/unregister控制，系统审批状态与应用本地偏好分开；不承诺绕过系统审批或实际登录验证。

## 2026-10-27 修正与可观察性

Apple DTS指出notFound也可能表示系统从未见过服务（https://developer.apple.com/forums/thread/719862）。主应用服务的notFound不能先行禁用注册入口：表现为尚未启用，仅在用户明确开启时register；成功、需审批或错误仍以系统真实返回为准，不自动注册来“探测”。未知未来状态保持不可用降级，不清理系统BTM。

自动检查继续沿用原6小时策略，并将既有lastAttempt作为只读值加入ClockSessionState，包含失败尝试且跨重启保留；手动检查不改变该记录，不把尝试时间当成功证明。页面动效明确为主面板/设置页的opacity过渡，不是装饰动效；系统减少动态效果优先。
