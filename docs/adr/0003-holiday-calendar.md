# ADR-0003：节假日采用逐日覆盖，调休上班日不影响价格

- 状态：已接受
- 日期：2026-10-23
- 决策者：项目维护者

## 背景

DeepSeek 官方文字：

> 北京时间周一至周五（不含中国法定节假日）9:00–12:00、14:00–18:00 为高峰时段；其余时段，包括周末及中国法定节假日全天均为空闲时段。

中国节假日安排包含「放假」与「调休上班」两部分。第三方工作日日历通常把调休周末标为工作日，但这不等于价格峰期。另有一些日历把“法定节假日”与“放假调休”混为一谈，导致覆盖不准确。

## 决策

1. 日期数据来自 **国务院办公厅年度节假日安排通知**（gov.cn），记录 URL、文号、核对日期与覆盖范围。
2. 使用 **日期范围** 表示放假（`holidays`），覆盖工作日的峰期。
3. `makeupWorkdays` 仅记录调休上班日，**不参与价格计算**；周末无论是否上班都是谷。
4. 不使用“是否工作日/是否上班”作为价格判断。
5. 每年新增一个日历文件（如 `calendar-2027.json`），更新 coverage 与 manifest；旧年份保留。
6. 覆盖范围之外的工作日显示「规则待更新」，不用通用日历猜测。

## 后果

正面：

- 与官方文字一致，尤其是补班周末。
- 数据可审计：每条日期都能追溯到政府公告。
- 引擎逻辑简单：假日 → 谷，周末 → 谷，其余工作日按窗口。

代价：

- 每年需要人工维护一次；2027 年安排公布前，跨年时段会显示待更新。
- 无法覆盖“临时调休”或地方性安排；官方未发布前不猜测。
- 日期覆盖必须显式声明，用户可能看到待更新状态而不是“大概正确”的时间。

## 备选方案

- **第三方工作日 API**：把“上班”误当“峰期”，与官方定义冲突，且引入网络依赖。
- **按农历自动计算**：只能得到传统节日，无法得到国务院调休安排。
- **把补班周六视为峰期**：与官方“周末为空闲”文字直接冲突。
- **长期无限覆盖**：会制造未经确认的精确状态，违反降级原则。

## 后续

- 2027 年安排发布后新增日历并测试春节/国庆的连续谷期。
- 若官方未来改变周末或补班定价语义，应更新需求与引擎，而不是只改数据。
