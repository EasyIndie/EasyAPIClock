# 提醒

目标：**持续显示安静，价格切换明确，强度可控。** 提醒不是营销通知，不重复轰炸，不在用户关闭后自行恢复。

## 分层

| 层 | 来源 | 作用 |
|---|---|---|
| 提醒策略 | `reminder-policy.json`（可更新） | 默认强度、提前偏移、强提醒重复参数、声音开关 |
| 本地偏好 | UserDefaults | 用户选择的强度、提前提醒开关；**永不被远程覆盖** |
| 计划器 | `ReminderPlanner`（纯逻辑） | 把快照 + 偏好 + 策略变成未来提醒 |
| 调度器 | `UserNotificationScheduler` | 请求权限、排程、替换、停止、系统设置入口 |
| 文案 | `ReminderCopy` | 由 `ReminderFacts` 生成标题/正文/副标题 |

## 默认值

- 强度：中等。
- 提前提醒：关闭。
- 中等：一次系统通知 + 系统默认声音，不循环。
- 强：切换通知 + 有界重复（默认 30 秒 × 10 次），带「停止提醒」。
- 重复总时长上限 30 分钟（校验强制）。

## 计划器

`ReminderPlanner(now:preferences:policy:).plan(for:)` 仅在以下条件都成立时产生事件：

- 强度不是 `off`；
- 当前状态已知；
- 下次切换已确认；
- 切换时刻严格晚于 `now`。

### 事件

| 事件 | 何时产生 | 触发时刻 | 重复 |
|---|---|---|---|
| 正式切换 | 总是（满足上述条件） | `nextChangeAt` | 仅强提醒，按策略 |
| 提前提醒 | 用户开启且策略有偏移 | `nextChangeAt - lead`，且必须晚于 `now` | 不重复 |

`ReminderFacts` 携带：

- `targetState`：即将进入峰还是谷；
- `comparison`：统一倍率/百分比，或 mixed；
- `upcomingWindowDuration`：新窗口持续时间（若可确认）；
- `leadSeconds`：提前提醒的偏移（正式切换为 `nil`）。

### 文案

- 进入谷期：`进入低价` / `单价比峰期低 50% · 持续 2 小时`
- 进入峰期：`进入高峰` / `单价为谷期 2 倍 · 持续 4 小时`
- 提前提醒：`5 分钟后进入高峰` / `单价将升为谷期 2 倍 · 持续 2 小时`

规则：

- 一条通知只保留标题与一行正文；正文用「价格基准 · 持续时长」结构，保证锁屏横幅一行可读完。
- 百分比、倍率、时长全部来自 facts，不写死。
- 必须明确「变贵 / 变便宜」以及下一窗口或持续时间。
- 统一倍率不成立时退化为「单价进入高峰价格时段 / 单价进入低价价格时段」。
- 系统通知头部已显示应用名；中等提醒不设副标题。强提醒副标题为 `持续提醒 · 可停止`，用于提示停止入口。
- 不再输出「距离下次低价还有……」这类与标题重复的第二句解释。

## 事件 ID 与去重

- 正式切换：`t:<transitionEpoch>`
- 提前提醒：`a:<leadSeconds>:<transitionEpoch>`
- 通知请求 ID：`lw.` + 事件 ID；强提醒重复追加 `.r1` … `.rN`

去重不依赖持久化账本：

1. 同一 ID 的新请求会替换未送达的旧请求；
2. 计划器只产生 `fireDate > now` 的事件，已过去的切换不会被重新计划；
3. 应用重启/唤醒后只排未来事件，不会补发历史。

这满足「同一切换只提醒一次」，也避免维护一个复杂的“已发送”状态机。副作用：如果用户在切换前关闭再打开应用，未来事件会以相同 ID 重新排程——仍然是同一个 pending 请求，不会重复送达。

## 重新排程（签名）

`ClockModel` 计算计划签名：

```
授权状态 + 规则包版本 + 每个事件的签名
事件签名 = id | 类型 | fireDate | 强度 | 目标状态 | 倍率 | 窗口时长 | 重复次数
```

只有签名变化才调用 `replacePlan`。好处：

- 每分钟刷新不会重置重复通知的计时；
- 强度、提前提醒、规则内容或授权变化会立即反映；
- 每分钟刷新不会反复删除/添加请求。

`replacePlan` 会先移除所有 `lw.` 前缀的 pending，再添加当前计划；空计划等于取消全部。

例外：**正在进行的强提醒重复会被保留**。切换发生后，计划器已经转向下一次切换；如果按“全部移除”处理，下一次每分钟刷新会取消还没播完的强提醒。`StrongRepeatRetention` 只保留满足以下条件的 pending：

- 属于 `lw.strong` 分类；
- 是重复请求（`.rN` 后缀）；
- 事件切换时刻仍在“重复间隔 × 次数 + 60 秒”的窗口内；
- 当前计划仍然是强提醒。

用户切到中等/关闭、点击「停止提醒」，或窗口结束后，重复会被移除。该规则有独立单元测试（`StrongRepeatRetentionTests`）。

## 强提醒与停止

- 正式切换事件按 `strongRepeatIntervalSeconds` 预排 `strongMaxRepeats` 个额外通知。
- 所有强提醒通知使用 `lw.strong` 分类，带「停止提醒」动作（`lw.stop`）。
- 点击停止：移除该事件所有未送达的重复通知，并移除已送达通知。
- 事件已经过去，刷新不会重新计划；因此停止后不会因下一次刷新再次响铃。
- 提前提醒在强模式下只响一次，不重复。

> 真实行为（应用在前台/后台/被终止、Focus、静音、睡眠唤醒）仍待验证，见 [`../ops/platform-validation.md`](../ops/platform-validation.md)。

## 权限

- 首次 `prepare()` 时，如果尚未决定且强度不是关闭，请求 `.alert` + `.sound`。
- 拒绝后不反复弹系统提示；设置中显示「系统通知未开启」并提供打开系统设置。
- `notDetermined` 时界面临时按强度显示，不误报「未授权」。
- 权限变化会在每分钟刷新时重新读取，并触发重新排程。

## 不补发

- 提前提醒错过（例如 08:55 在睡眠，08:56 唤醒）→ 跳过，不延迟发送。
- 正式切换在睡眠期间已过 → 不补发；刷新后直接进入新状态，计划下一次切换。
- 启动、唤醒、改时、规则更新后都不会集中发送历史通知。

## 平台限制

| 能力 | macOS | iOS |
|---|---|---|
| 本地通知 | ✅ 需权限 | ✅ 需权限 |
| 应用退出后已排定通知 | ✅ 通常由系统送达；不会重排 | ✅ 由系统调度 |
| 强提醒持续响铃 | ◐ 有界重复通知；无 critical alert 权限 | ◐ 同左；后台限制更严格 |
| 穿透静音 / 专注模式 | ⛔ 系统决定 | ⛔ 系统决定 |
| 后台规则更新 | ◐ 启动/前台/手动 | ◐ 更受限，不承诺实时 |
| 停止动作 | ✅ 通知动作；终止状态未验证 | ✅ 系统动作；未验证 |
| 独立浮层 / 抢焦点 | ⛔ 未实现 | ⛔ 未实现 |

应用不请求 Critical Alerts、辅助功能、Apple Events 或屏幕录制权限。

## 失败与降级

| 情况 | 行为 |
|---|---|
| 规则未知/切换未确认 | 不产生计划；底部「提醒暂停」 |
| 提醒关闭 | 取消所有 pending；时钟继续 |
| 通知被拒绝 | 时钟继续；设置提示；不静默假装已提醒 |
| 强提醒参数异常 | 规则包校验失败，整包拒绝 |
| 系统丢弃通知 | 无法感知；不重试轰炸 |

## 用户主动预览

预览独立使用 `gudeng.preview.<UUID>.<index>` ID，与正式 `lw.` 排程互不替换。中等一次，强最多三次；本地10秒清理任务可取消。取消后如异步add已完成，仍按唯一ID清理该轮请求，不清理新轮或正式事件。未授权只反馈失败，不请求权限。离开设置、强度变更和应用退出调用stopPreview。通知正文明确为测试，不从演示数据伪造价格变化。

### Debug验收观测

仅Debug构建且设置 `GUDENG_NOTIFICATION_DIAGNOSTICS=1` 时，标准输出记录本应用预览的真实pending/delivered ID、授权状态、正式pending数量及willPresent回调。2/5/8秒采样任务在停止时取消；不读取其他应用通知或正式通知正文，不改变正式排程。Release不包含该观测代码。采样仅作为平台验收证据，排入成功不等于用户看到或听到通知。

Debug启动时还可只读记录全部本应用预览前缀的pending/delivered集合，快照自身不清理通知，供验证正常退出后的残留；仍受同一显式环境标志控制，Release不包含。

2026-10-27 Debug预览诊断补充alerts/sound/notificationCenter/style，只读取本应用UNNotificationSettings并转为Sendable字符串后输出。authorized不代表所有呈现设置开启；即使设置开启，delivered也不等于用户看见横幅或听到声音。没有修改系统权限或Focus。
