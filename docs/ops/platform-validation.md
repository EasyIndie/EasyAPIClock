## 为什么要单独验证

单元测试只能证明“计划正确”，不能证明系统真的送达。以下行为依赖 macOS/iOS 版本、权限、Focus、静音、通知中心策略、应用生命周期与签名状态：

- 通知是否显示、是否响铃；
- 强提醒重复是否能被“停止”打断；
- 面板关闭、进程退出、系统睡眠后是否仍送达；
- 唤醒后是否补发历史通知；
- 权限被拒绝/撤销后的行为；
- 点击通知是否激活应用（当前不会自动展开面板）。

## 如何制造一个近期的切换

三种方式，按风险从低到高：

1. **等待真实边界**（推荐）：工作日 08:59、11:59、13:59、17:59 前 1–10 分钟启动应用。默认中等提醒会在切换时触发。
2. **本地规则源（推荐）**：

```bash
# 生成一个 3 分钟后进入峰期的测试包，并启动 localhost 服务器
make serve-test-rules

# 测试提前提醒时，让峰期在 7 分钟后开始
Scripts/serve-test-rules.sh --lead-minutes 7
```

脚本会复制 `Rules/` 到 `.build/test-rules`，只修改临时包，重新计算 manifest，并打印启动命令。另开终端：

```bash
make build-mac-adhoc
LIANGWEN_RULE_SOURCE=http://127.0.0.1:8765 \
  .build/DerivedData/Build/Products/Debug/LiangWenMac.app/Contents/MacOS/LiangWenMac
```

然后在设置中点击「检查更新」。测试包只用于验证，不要提交或发布。**周末恒为谷，脚本会拒绝生成；请在工作日运行。** 测试结束后清理 active 规则，回退内置版本：

```bash
rm -rf ~/Library/Containers/app.liangwen.mac/Data/Library/Application\ Support/LiangWen/Rules/active
```
3. **修改系统时间**：可以验证唤醒/重算，但会影响其他应用与通知计时；测试后立即恢复，并记录风险。

## macOS 检查清单

### 安装与基础

- [ ] 在干净用户账户安装/启动；Gatekeeper 行为符合预期（开发构建可豁免）。
- [ ] 菜单栏出现状态项；Dock 无图标；无主窗口。
- [ ] 首次启动请求通知权限；拒绝后应用仍可用。
- [ ] 设置中显示真实规则版本、覆盖范围、来源与核对日期。
- [ ] 修改强度/提前提醒后重启应用，偏好保持。

### 中等提醒

- [ ] 切换时只收到一次通知和一次短音。
- [ ] 关闭面板、但进程仍在时，通知送达。
- [ ] 通知标题/正文与当前规则一致（倍率、时长）。
- [ ] 通知不会每分钟重复。
- [ ] 通知权限为“横幅”/“提醒”/“无”时分别记录行为。

### 提前提醒

- [ ] 开关默认关闭；开启后标签显示策略偏移（5 分钟）。
- [ ] 切换前 5 分钟收到一次提前提醒；正式切换仍提醒。
- [ ] 提前提醒在睡眠中错过时，不在唤醒后补发。
- [ ] 修改提前偏移的策略包后，标签与行为更新。

### 强提醒

- [ ] 选择强提醒后，切换时出现重复通知（默认 30 秒 × 10）。
- [ ] 每次重复都带「停止提醒」操作。
- [ ] 点击停止后，后续重复不再出现，已送达通知被移除。
- [ ] 停止后再次刷新/重启，同一事件不重新响铃。
- [ ] 面板关闭后停止入口仍可达（通过通知中心）。
- [ ] 记录是否抢焦点、是否阻塞其他应用。

### 生命周期

- [ ] 面板关闭 ≠ 退出进程；关闭面板后仍提醒。
- [ ] 主动退出应用后：已排定通知是否送达？重启后是否重复？
- [ ] 睡眠跨过切换：唤醒后状态正确，无通知轰炸。
- [ ] 系统时间手动调整：重算正确，不补发历史。
- [ ] 系统时区切换：状态仍按北京时间。
- [ ] 应用长时间运行：菜单栏宽度不抖动，倒计时按分钟更新。

### 权限与系统设置

- [ ] 拒绝权限后，设置显示「系统通知未开启」，按钮打开正确的系统设置页。
- [ ] 在系统设置中重新允许后，应用在下一次刷新恢复排程。
- [ ] 专注模式/静音下记录：通知是否显示、是否响铃、强提醒是否仍重复。
- [ ] 低电量模式（如适用）下的行为。

### 规则更新

- [ ] 规则源不可达 / 404 时，按钮给出明确说明，不报错弹窗，旧规则继续可用。
- [ ] 成功更新：版本/覆盖/来源变化，提醒按新规则重排。
- [ ] 坏包：失败提示，旧规则继续可用。
- [ ] 未来生效：显示待启用，当前状态不变，到期后启用。
- [ ] 更新本身不触发一次价格切换通知。

### 可访问性

- [ ] VoiceOver 朗读菜单栏、状态、价格行、倒计时、底部摘要。
- [ ] 仅用颜色无法区分时，文字仍清晰（峰/谷、梁文峰/梁文谷）。
- [ ] 键盘可操作设置控件。
- [ ] 浅色/深色/高对比度下可读。

## 退出标准（M1）

- 中等、强、提前、关闭四种路径各至少 3 次成功记录。
- 睡眠/唤醒、退出/重启、权限拒绝/恢复各有一次记录。
- 任何“受限”行为写入设置说明、README 与 `docs/architecture/reminders.md`。
- 未通过项有 issue 或明确的产品降级，不隐藏。

## 已知限制（验证时重点确认）

- 强提醒是重复通知，不是浮层；无法覆盖专注模式/静音。
- 没有 Critical Alerts 权限，不能保证穿透系统静音。
- 应用退出后不会重新排程；已排定通知可能仍送达。
- 规则更新只在启动/刷新/手动检查时发生，不承诺后台实时。
- 当前通知点击只激活应用，不会自动展开面板。
- ad-hoc 签名的开发构建与正式签名构建在通知/沙盒行为上可能不同。
