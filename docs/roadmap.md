# 路线图

## 当前：v0.1.0 工程脚手架（2026-10-23）

已完成：

- 纯逻辑规则引擎、北京时间与节假日语义、下次真实切换。
- 规则包完整性、原子安装、未来生效、失败回退。
- 提醒计划与文案、macOS 菜单栏应用、内嵌设置、本地偏好。
- 2026 价格与节假日数据、56 个单元测试、CLI、CI、开源文档。

明确未完成：签名/公证、图标、真实设备通知验证、iOS 设计、英文界面、规则数字签名。

## M1：可发布（P0）

目标：可以对外提供一个可信、可安装的 macOS 预览版。

- [ ] 真实设备通知矩阵验证（Focus、静音、睡眠、退出、强提醒停止）。
- [ ] Developer ID 签名、Hardened Runtime、公证、DMG/zip。
- [ ] 应用图标与菜单栏图形资产；README 真实截图。
- [ ] 规则托管与一次成功更新、一次坏包回退演练。
- [ ] 版本号、CHANGELOG、发布说明、隐私说明。

发布门槛：`make check` 通过；A15 有记录；签名与公证通过 `spctl`。

## M2：数据韧性（P1）

- [ ] Ed25519 规则签名与内置公钥、密钥轮换/撤销流程。
- [ ] 2027 年节假日日历与跨年测试。
- [ ] 规则发布自动化（校验和、清单、上传、回滚）。
- [ ] 更新源缓存/CDN 策略与可用性监控（仅维护者侧）。

## M3：iOS 正式化（需产品决策）

- [ ] iOS 页面与交互设计确认。
- [ ] 通知能力验证（前台/后台/退出/Focus/静音/强提醒）。
- [ ] 设置与本地偏好。
- [ ] 替换当前只读外壳；删除“未设计”提示。

在设计与平台验证完成前，不承诺 iOS 发布时间。

## M4：国际化与可访问性

- [ ] String Catalog，英文（至少）与日期/时长本地化。
- [ ] VoiceOver、对比度、动态字体、键盘完整审计。
- [ ] 文档英文摘要与贡献指南。

## 开放问题

1. 强提醒是否值得做独立浮层？需要设计确认与平台验证。
2. 应用退出后已排定通知的可达性如何向用户解释？
3. 规则包签名密钥由谁持有、如何轮换？
4. 分发渠道：Developer ID 直发、Mac App Store，还是两者？
5. 2027 年节假日安排发布前，跨年用户体验如何提示最清晰？
6. 是否需要“检查更新”之外的自动检查频率？后台能力如何限制？
7. 是否提供锁定到某个历史规则包的能力（用于审计/复现）？
8. 首次启动即请求通知权限是否合适，还是等用户第一次打开设置/选择强度时再请求？

## 明确不做

- 账号、API Key、Token 统计、消费分析。
- 番茄钟、任务管理、Agent 集成、自动切换模型。
- 主界面完整价格表、图表、复杂日历。
- 硬件配网/设备管理。
- 可视化规则编辑器。
- 在未授权情况下发布、上架或购买服务。
