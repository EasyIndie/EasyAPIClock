# 路线图

## 当前：1.0.0 已发布（2026-10-28）

1.0.0 是首个公开 MVP，仅 macOS：

- Developer ID 签名、Apple 公证、staple、Gatekeeper、SHA-256/manifest 校验均完成。
- 已验证 macOS 27.0.1 arm64 与 macOS 13.7.8 Intel；macOS 14/15 与 macOS 13 arm64 未实测，发布说明已披露。
- 北京时间规则、真实切换、提醒、规则包完整性/回退、菜单栏与设置均已实现。
- 内置 2026 价格与节假日规则，覆盖至 2026-12-31。

已接受的限制：声音听感、Focus/静音、睡眠唤醒、登录项重登录、真人点击停止与可访问性仍待补验；这些不阻塞 1.0.0，但不能在后续文档中写成已通过。

## 1.0.x：维护与时间门槛

目标：让已发布版本稳定跨过 2026 年，不引入新功能。

- [ ] **2027 节假日日历（P0，硬门槛 2027-01-01）**：国务院安排发布后新增 `calendar-2027.json`，更新 coverage、manifest、来源与测试，通过 Rules workflow 发布。官方截至 2026-10-28 尚未发布，保持「规则待更新」，不得推测。
- [ ] 规则源可用性：确认 raw manifest 可读、checksum 一致；记录一次 CDN 传播时延与坏包/回滚演练。
- [ ] 发布收尾自动化：确认 `release-notes` 重试生效；每次发布检查 Release body 与资产。
- [ ] 只修 P0/P1 缺陷；如改应用代码，递增 build/build 版本并重新公证，不覆盖 `v1.0.0` tag。

## 1.1.0：下一阶段迭代（草案）

主题：**跨平台可信度 + 通知交互 + 可访问性**。不扩大 MVP 的产品范围。

### P0 · 平台与生命周期证据

- [ ] 在可用设备/虚拟机上补测 macOS 14/15 与 macOS 13 arm64；没有设备时继续如实标注，不声称通过。
- [ ] 记录 Focus/静音、睡眠跨切换、唤醒、登录项重新登录、真人点击停止、声音听感的通过/受限/失败。
- [ ] 验证跨分钟、跨日、系统改时/时区、退出后送达与重启不重放；发现的问题先补固定时间测试。

### P1 · 通知交互

- [ ] 评估并实现通知点击打开面板或设置；无法可靠实现时在设置与文档中明确说明。
- [ ] 复核强提醒有界重复与停止路径，确保同一事件只安排一次、用户关闭后立即取消 pending。
- [ ] 不引入独立浮层，不承诺穿透 Focus/静音/系统限制。

### P1 · 可访问性

- [ ] VoiceOver 朗读、键盘焦点、对比度、动态字体、减少动态效果/透明度逐项记录。
- [ ] 修复设置滚动、按钮标签、状态色等可访问性问题；保持 334×322pt 面板与现有视觉基准。

### P1 · 规则韧性

- [ ] 用 2027 日历更新作为一次完整跨年演练：候选、校验、发布、客户端生效与覆盖边界。
- [ ] 评估规则源健康告警（只告警，不自动改数据）与灰度/CDN 策略。
- [ ] Ed25519 规则签名仍在后续版本评估，不混入 1.1.0 的 UI 改动。

### 验收 / 退出条件

- 2027 规则在 2027-01-01 前可发布，且覆盖不足时仍正确降级。
- 平台矩阵有证据；未测系统在发布说明中明确列出，没有未披露的 P0 缺陷。
- 通知点击/生命周期/可访问性有可复核记录；`make check` 与公证发布通过。
- 从 1.0.0 升级保留偏好、通知授权与规则回退行为。
- 不新增账号、API Key、价格图表、自动切换模型、iOS 交互或英文界面。

## 后续（1.2+）

### 数据与信任

- [ ] Ed25519 规则签名、内置公钥、密钥轮换/撤销流程与 ADR。
- [ ] 规则包 CDN/灰度发布策略与维护者侧可用性监控。

### 平台与国际化

- [ ] iOS 页面与交互设计确认、通知能力验证、正式实现；设计完成前不承诺时间。
- [ ] String Catalog 与英文界面；日期/时长本地化；英文贡献指南。
- [ ] App Store 可行性评估；不承诺上架。

### 产品边界外

账号、API Key、Token 统计、消费分析、番茄钟、任务管理、Agent 集成、自动切换模型、硬件配网、完整价格表/复杂日历、可视化规则编辑器。未经授权不发布、不公证本地包、不上传规则或创建 Release。

## 开放问题

1. 无 macOS 14/15 与 13 arm64 设备时，是否接受长期以“未实测”披露，还是投入虚拟机/借用设备？
2. 通知点击打开面板是否能在不引入常驻窗口的前提下可靠实现？
3. 2027 安排发布前，跨年用户提示是否需要单独的状态文案？
4. Ed25519 密钥由谁持有、如何轮换与撤销？
5. 分发渠道继续 Developer ID 直发，还是评估 Mac App Store？
6. 自动规则检查频率是否需要调整，如何在系统限制下保持可预期？
