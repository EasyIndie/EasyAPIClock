以下正文可以直接交给接手开发的 AI 代理。将整个文件夹一起提供，避免丢失设计稿。

请根据随附的梁文钟交接包推进开发。先阅读 README、产品计划、需求规则、设计规范，并在浏览器中打开 `design-preview.html`。不要把演示交互当成生产实现。

## 产品目标

梁文钟是极简的 API 价格时段时钟。首版面向 macOS 和 iOS；Mac 已确认形态为常驻状态栏小工具，点击展开后只显示峰谷状态、模型单价差异和下次切换倒计时。其余进入设置，默认中等提醒，强提醒由用户主动选择。

视觉以随附简洁交互稿为基准，不能回退到信息繁杂的版本或擅自增加功能。对外只介绍 API 峰谷定价灵感，不介绍人名来源。

## 开发前先做

1. 盘点所给项目环境；若没有仓库或工程，先提出最小结构和平台方案。技术栈尚未定稿，不把网页稿的 HTML 视为生产技术选择。
2. 重新核对 DeepSeek 官方价格页，记录来源与时间；当前快照供理解，不作为永久真值。
3. 核实周末、法定节假日与调休补班的价格映射，说明日期数据来源与覆盖范围；不能使用“是否上班”直接替代定价规则。
4. 说明 Mac 与 iOS 实际通知能力，尤其是持续提醒、主动退出、休眠、后台更新、权限、静音与专注模式的限制；不能先承诺做不到的体验。
5. 给出精简实现方案、首个可运行里程碑和关键待决事项。iOS 页面尚未设计，先给出最小页面方案，不擅自声称现有 Mac 稿覆盖了 iOS。

## 实现要求

- 分离价格规则、日期例外、提醒策略、执行机制、本地偏好。
- 声明式配置可更新，不执行远程脚本。首版不做通用策略编辑器。
- 默认中等提醒；强提醒可停止；远程更新不能覆盖用户强度。
- 内置离线规则，更新须校验并完整替换，失败保留有效旧数据；有效性不足时明确待更新并暂停相应提醒。
- 所有价格时段按北京时间计算；倒计时跨日正确；真实状态不变时不发午夜提醒。
- 同一事件去重；启动 / 唤醒时不集中补发历史通知；更新后重新安排未来事件。
- 倍率由价格规则计算，比较基准清楚；不宣称全部 API 费用减半，不承诺跨时段请求锁价。
- 不做番茄钟、账号、API Key、统计、消费分析、任务管理、自动切换模型、Agent 集成或硬件管理。
- 未来 ESP 只预留轻量规则语义，不提前开发硬件功能。

## 验证和交付

按需求文件列出的验收场景覆盖边界、周末、节假日、规则有效性、更新失败、提醒强度和去重。使用真实有价值的规则与状态测试，并在目标平台验证通知；不以网页模拟运行正常替代原生验证。

交付时给出可运行版本、运行步骤、验证结果、平台限制和剩余事项。新增需求与范围变更必须明确说明。没有独立授权时，不发布、不上架、不购买服务。

本任务不要求原封不动复用网页代码；应复现已确认的简洁视觉与交互，并真正实现规则和通知机制。
